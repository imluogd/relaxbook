# 个人电子书听书应用 Intent

版本：v0.2 需求确认稿（技术选型待验证）  
日期：2026年11月22日  
定位：个人使用优先，中文为主，兼顾英文

让用户把已有电子书转成可长期保存、按章节收听的有声书，在 Android 和 iOS 手机上少看屏幕、持续阅读。电脑端通过网页完成操作，后台负责文本处理和语音生成，手机主要负责播放。

建议先验证“现成转换工具 + 标准音频文件 + 现成手机播放器”的完整流程，再根据实际缺口决定是否开发自己的 App。本阶段交付 intent 与调研结论；中文听感、转换速度和手机兼容性仍需下一阶段用真实书籍验证。

## 用户意图与成功体验

日常办公已经占用大量视觉注意力，用户仍希望保持阅读习惯，因此需要把一部分阅读迁移到听觉。核心价值是减少持续盯屏和操作的时间，并保留完整书籍的内容与章节结构。

已确认的需求：

- 中文书为主，兼顾英文。
- 先满足个人使用，优先复用成熟工具。
- 输入覆盖 PDF、EPUB、MOBI、AZW3 等电子书格式。
- 可选择音色；电脑端以网页提供书籍导入、目录检查、音色试听、转换进度和音频下载。
- 手机端面向 Android 与 iOS，具备章节目录和播放能力。

核心使用情境：用户在电脑浏览器中打开网页，导入一本书，检查目录和正文、试听音色后启动后台转换；把生成的有声书传到手机，出门后断网也能从上次位置继续听，锁屏时仍可控制播放。

已确认的体验要求：离线播放、断点续播、倍速、睡眠定时和锁屏控制。两种手机系统可以先使用不同的成熟播放器，不要求第一阶段就拥有统一界面的自研客户端。

## 市场上已有的相近产品

市场已有“文档朗读”和“有声书播放”两类成熟产品。能在 App 中听电子书，不代表可以导出带章节的音频文件。

| 产品或组合 | 与需求相符的能力 | 需要关注的差异 |
| --- | --- | --- |
| NaturalReader | Web、Android、iOS；支持 PDF、非 DRM EPUB；可选择语音并生成 MP3 | MP3 导出需订阅；帮助文档规定分页文档单次最多转换 20 页，长书需分批；未据此确认能导出完整章节结构。见[产品说明](https://help.naturalreaders.com/en/articles/8584530-what-is-naturalreader-ai-text-to-speech-personal-version)及[音频导出说明](https://help.naturalreaders.com/en/articles/11543218-working-with-text-and-audio-personal-version)。 |
| ElevenReader | Android、iOS；导入 PDF、EPUB 等文件，选择音色收听 | 适合直接听读。符合条件的付费订阅支持应用内离线下载，但缓存有有效期；官方导出说明将音频导出指向其 Web 平台，不能把 Reader 的缓存当成可迁移音频文件。见[Android 功能](https://elevenlabs.io/docs/help-center/product/mobile-apps/elevenreader/how-to-guides-for-elevenreader/how-to-use-elevenreader-on-android)、[iOS 功能](https://elevenlabs.io/docs/help-center/product/mobile-apps/elevenreader/how-to-guides-for-elevenreader/how-to-use-elevenreader-on-iphone)、[离线说明](https://elevenlabs.io/docs/help-center/product/mobile-apps/elevenreader/how-to-guides-for-elevenreader/how-do-offline-downloads-work)和[导出说明](https://elevenlabs.io/docs/help-center/product/mobile-apps/elevenreader/can-i-download-audio-from-elevenreader)。 |
| 电脑转换 + Voice / BookPlayer | 自己保存音频；Android 用 Voice，iOS 用 BookPlayer；均提供章节导航、播放进度、倍速和定时等听书功能 | 最接近个人使用的轻量路线；电子书解析和语音生成由电脑工具承担，传文件需单独完成。见[Voice](https://github.com/PaulWoitaschek/Voice)与[BookPlayer](https://github.com/TortugaPower/BookPlayer)。 |
| 电脑转换 + Audiobookshelf | 自建有声书库、跨设备进度、章节管理，配套移动端 | 增加服务端维护；官方 iOS 客户端仓库目前标为测试版且提示名额已满，不宜作为唯一 iOS 路径。见[服务端](https://github.com/advplyr/audiobookshelf)与[移动端](https://github.com/advplyr/audiobookshelf-app)。 |

**判断：已有方案足以成为验证起点，现阶段没有证据表明必须从零开发。** 自研的潜在价值主要是把导入、章节修正、中文音色试听、失败重试和传到手机这些步骤连成顺畅流程。是否值得开发，应由个人试用暴露出的具体问题决定。

## 已确认的最小可用范围

这里的最小可用版本指一套能稳定使用的个人听书流程：电脑端使用网页，手机端先复用现成播放器。网页可以由本机服务提供，使用浏览器访问 localhost；网页界面不等于必须部署公网或上传书籍。建议先采用本地网页加后台转换任务，后续需要时再迁移到服务器。首次安装和启动服务允许独立于网页，日常导入、试听、转换和下载在网页内完成。

### 电脑端

| 能力 | 第一阶段要求 |
| --- | --- |
| 导入与检查 | 接受无 DRM、可读取的 EPUB、MOBI、AZW3、文本型 PDF；报告格式错误、无可提取文本及解析失败。 |
| 章节提取 | 按书籍目录及正文阅读顺序建立章节；支持检查标题、顺序和开头结尾，必要时人工修正。 |
| 正文清理 | 处理页眉、页脚、页码、异常换行和重复内容；脚注等内容可选择保留或跳过，避免静默丢失正文。 |
| 音色选择 | 至少比较两种中文候选音色，并验证一种英文能力；可用书中同一段文字试听后再生成全书。 |
| 音频生成 | 按章或更小片段生成，显示进度；保存成功结果，失败部分可重试，避免整本书重复生成。 |
| 输出 | 默认将每章保存为独立 MP3，按顺序和章名自动命名，可单独下载；需要时可打包 ZIP 或导出带目录的整书 M4B。 |
| 移交手机 | 第一阶段允许通过数据线、系统文件导入或已有文件同步工具传输，记录一套可重复操作的方法。 |

EPUB 作为优先验证输入。MOBI、AZW3 可借助格式转换进入同一流程；若原始目录异常，应允许修正。PDF 单独处理阅读顺序与目录：有书签时优先利用书签；没有可靠章节结构时提供人工分章或明确标记的分段，不能把任意切片伪装成原书章节。calibre 也明确指出 PDF 转换容易遇到问题，见[官方 PDF 转换说明](https://manual.calibre-ebook.com/faq.html#i-converted-a-pdf-file-but-the-result-has-various-problems)。

扫描 PDF 和复杂多栏 PDF 建议放到后续阶段，由 OCR 与版面解析补充。第一阶段必须识别并提示这类文件，不能输出空音频或错误顺序后宣称成功。

### 手机端

- 按书组织音频，显示书名、章节、当前进度和剩余时长。
- 播放、暂停、上下一章、前后跳转和倍速。
- 记忆每本书的播放位置，关闭再打开仍能续播。
- 后台及锁屏播放，支持耳机控制和来电等中断恢复。
- 离线收听、睡眠定时、书签及删除已下载音频。
- Android 与 iOS 均有可用路径；第一阶段不强求跨系统自动同步进度。

“选择音色”默认发生在生成前。手机上的倍速可立即调整；已经生成的音频更换音色需要重新生成，对应的是另一份有声书版本。

## 处理流程与职责边界

网页导入电子书 → 后台检查格式与文本 → 提取正文和章节 → 网页检查与修正 → 音色试听 → 后台分段生成语音 → 封装有声书 → 网页下载并传到手机 → 离线播放与续播。语音生成需要 TTS（文本转语音）引擎；采用神经语音合成时需要相应模型，但不必另外调用通用文本大模型来理解、改写或总结整本书。部分 TTS 本身采用大模型架构，这与额外接入文本 LLM 是两种依赖。目录解析、文件转换和音频封装通常由常规程序完成；扫描件另外需要 OCR。TTS 可在本机运行，也可调用云端服务，网页形态不决定模型运行位置。

章节的语义识别放在电脑端，手机读取音频内的章节信息或按章排列的文件。这样不会在两端重复解析 PDF、EPUB 等复杂格式。

电脑后台保留可修正的正文、章节清单和转换任务记录，优先复用选定转换工具已有的数据结构；仅为缺失能力增加必要字段。生成记录至少包含来源文件、引擎与模型版本、音色、参数、完成状态和失败片段。手机书库、书签、倍速设置和播放进度由现成播放器管理，本项目不直接读写其内部数据库。重新生成的音频作为新版本导入，不承诺旧进度自动迁移。这些属于后续实现原则，不预先锁定数据库或接口格式。

电脑与手机之间以播放器支持的音频文件格式交换数据：默认使用按书归档的独立 MP3，例如 001 - 序言.mp3。可选的 M4B 通过内嵌目录组织章节。两种方式的排序与跳转均通过手机导入测试确认。复用的是播放器的导入和播放能力，无需照搬或共享 Voice / BookPlayer 的内部数据结构；自定义 JSON 只供自己的后台或未来客户端使用，不能假设现成播放器会读取它。

如以后引入 Audiobookshelf，电脑或 NAS 承担书库服务；书籍下载到手机后，离线收听不应依赖电脑持续开机。文件直传路线继续保留。

## 暂不纳入第一阶段的能力

- 自研或训练 TTS 模型、手机端生成整本书。
- 声音克隆、角色配音、情绪表演和背景音乐。
- 电子书商店、内容社区、公共有声书分发和商业订阅体系。
- 自动破解 DRM，或把无法读取的受保护文件当成普通格式问题。
- 复杂图表、公式、代码及多栏版面的完整语音解释。
- 全文逐字高亮、语音与原文精确对齐、多端进度自动同步。
- 用大模型概括或改写原书作为默认处理步骤。

第一阶段保留原书内容和顺序。文本规范化应尽量可追溯，避免为了“读起来顺”而改变作者原意。

## 验证方案与建议验收标准

以下是下一阶段的目标，不是已完成的测试结果。

选用个人有权使用的样本：两本中文 EPUB、一本英文 EPUB、一本文本型 PDF、MOBI 与 AZW3 各一份，再加一份扫描 PDF 用于验证识别和提示。另准备含多音字、人名、日期、金额、英文缩写及中英混排的短段落。

| 验证项 | 建议通过条件 |
| --- | --- |
| 四种格式 | EPUB、文本型 PDF、MOBI、AZW3 均完成至少一次“导入到手机播放”；允许预转换，需记录实际步骤。 |
| 章节完整性 | 样本章节标题、顺序及数量与人工核对清单一致；不存在静默漏章、重复章或空章。 |
| 正文完整性 | 每章核对开头和结尾，抽查中段；无明显跨页错序、整段漏读、重复或截断。 |
| 音色听感 | 用户试听至少两种中文音色，各连续听 10 分钟，选出愿意长期听的一种；记录多音字、数字及中英混排问题。 |
| 整书稳定性 | 至少完整生成一本中文书，检查失败记录并抽听；正常段落不因局部失败而反复生成。 |
| 手机播放 | 在 Android 和 iOS 各验证章节跳转、倍速、锁屏、耳机控制、来电中断与恢复。设备不齐时标记该平台未验收。 |
| 离线与续播 | 手机断网、电脑关闭后连续播放 30 分钟；关闭并重开播放器，续播偏差建议不超过 5 秒。 |
| 失败恢复 | 中断一次转换并恢复；已成功片段可以复用，错误能定位到章节或片段。若工具不支持，记录为需补齐的缺口。 |
| 性能与费用 | 记录电脑配置、输入字数、生成耗时、音频时长、文件大小和实际费用，再决定整书等待时间与预算上限。 |

先用同一批短文本比较候选，再跑整章和整书。音色不合格时先换引擎；正文不完整时先修解析流程；只有手机端交互确实影响日常使用时，才进入自研客户端设计。

若使用云端 TTS，生成前应清楚展示上传正文的范围及预计计费量。具体供应商、价格和可接受预算留到试听与小样测量后决定，本阶段不承诺整本书的成本或速度。

## 路线选择与待决策事项

推荐按以下顺序推进：

1. **验证现成组合。** 对比 ebook2audiobook 的 Web 界面与 abogen 的 Web UI，验证网页导入、试听、任务进度及单章 MP3 下载和可选的整书 M4B 导出；Android 使用 Voice，iOS 使用 BookPlayer。用实际结果选择转换工具与音色。现成网页未覆盖的必要操作，再通过轻量封装补齐。
2. **补齐实际缺口。** 如果问题集中在导入、章节修正、失败恢复或传文件，优先做电脑端轻量封装和流程整理。
3. **需要时增加书库同步。** 评估 Audiobookshelf，并单独确认手机安装渠道、客户端下载和进度同步行为。
4. **有明确收益时开发 App。** 只有现成播放器无法满足关键需求，或分散流程持续造成操作负担时，才投入统一的 Android / iOS 客户端。技术框架在这一阶段再选。

尚需后续确认：

| 问题 | 对方案的影响 |
| --- | --- |
| 实际常用手机系统、是否有双平台测试设备 | 决定先验证哪一端，以及双端验收条件。 |
| 电脑 CPU、GPU、显存、内存及可接受等待时间 | 决定本地引擎与是否需要云端备用路线。 |
| 能否接受正文上传第三方及单本或每月预算 | 决定可选语音服务；没有明确选择前以本地方案验证。 |
| 常读书籍类型、扫描 PDF 比例和每月阅读量 | 决定 OCR、复杂排版和批处理的优先级。 |
| 是否必须跨设备续播，是否愿意维护常开服务 | 决定文件直传是否足够，或引入 Audiobookshelf。 |

**阶段完成条件：** 找到用户愿意长期收听的中文音色，打通书籍导入到手机章节播放的流程，并能明确指出仍需开发的部分。如果现成组合已经满足这些条件，个人使用目标即可先行达成。

资料核对日期为 2026年11月22日。产品能力依据上文链接的官方文档和项目仓库；商店地区可用性、具体模型配置、中文听感及设备表现，以实际试用为准。
