# 个人电子书听书工具 实现规格 v1

依据[已确认的 Intent v0.2](./intent.md)。本规格用于第一版开发与验收。文中的性能、听感和真机兼容性均为待测项。

## 从一本书到手机续听

在配置好的电脑上启动服务，浏览器打开本地网页。用户选择一本书，核对目录，用书中同一段正文试听多个音色，选定后生成整书。同一批合成片段默认导出两种成品。手机首选一本一个 M4B，文件内含章名与起止时间。同时每章保存为独立 MP3，支持单章下载和可选的 ZIP 打包。Android 用 Voice 打开，iOS 用 BookPlayer 从“文件”导入。手机保存自己的进度，电脑关机后仍可继续听。[Voice](https://github.com/PaulWoitaschek/Voice) · [BookPlayer](https://github.com/TortugaPower/BookPlayer)

代码由一个远程 Git 仓库维护。每台电脑单独安装运行环境和模型，使用自己的书库、缓存和任务记录。首版采用桌面浏览器与本机后台。将来可把同一服务部署到云服务器，公网部署、账号、跨设备同步在后续版本设计。

## 技术选择与复用顺序

**先验证整套工具。** 取一份有三个章节的中文 EPUB 和一份真实文本 PDF，分别在 abogen Web UI 与 ebook2audiobook Web UI 上执行导入、目录核对、同段试听、转换中断恢复、带内嵌章节的 M4B 导入手机、单章 MP3 下载及结果清单核对。每项记录工具版本、操作、产物和缺口。通过核心流程的工具直接复用网页与后台，仓库提供固定版本、启动入口、配置和补充功能。两个都通过时选人工步骤较少、中文试听更满意的一套。项目说明确认两者有 Web 入口，具体恢复粒度和网页能力以实测为准。[abogen](https://github.com/denizsafak/abogen) · [ebook2audiobook](https://github.com/DrewThomasson/ebook2audiobook)

**需要补功能时的实现基线。** Python 3.11、FastAPI、Jinja2 模板和少量 JavaScript 提供本地网页。SQLite 保存任务和编辑稿，单独的 Python 工作进程执行转换。浏览器每两秒查询状态。复用 calibre 做格式转换、pypdf 与 pdfplumber 读 PDF 书签和文本、FFmpeg 与 ffprobe 封装并检查音频。优先调用候选工具公开支持的入口；仅有整书调用能力时，可按已确认的章节或文本片段分别传入，并由本项目管理重试。若适配成本超过直接集成语音引擎的成本，采用下述本地 TTS 接口。上述是本项目的设计选择，第三方工具内置的私有 HTTP 接口不作为依赖。

用户在《爱弥儿》同文试听中选定 Qwen 龙安灵心有声书朗读指令版。配置北京地域的 `DASHSCOPE_API_KEY` 后，试听和整书默认使用 `qwen-audio-3.1-tts-plus`、`longanlingxin_v3.1` 和同一朗读指令。应用经 WebSocket 向百炼发送朗读片段，按服务用量计费。音频缓存、章节管理与封装在本机执行。[百炼语音合成](https://help.aliyun.com/zh/model-studio/qwen-audio-3-1-tts-plus)

断网时可使用本地语音。离线基线采用 sherpa-onnx 的中英双语 Kokoro 模型，按包内映射加载音色，支持 CPU。首次下载模型并校验后即可在本机生成音频。解析目录、清理正文与封装音频使用常规程序，核心流程只需 TTS。[模型与运行说明](https://k2-fsa.github.io/sherpa/onnx/tts/pretrained_models/kokoro.html)

## 网页操作与异常反馈

| 页面 | 用户操作 | 服务返回的结果 |
| --- | --- | --- |
| 书库 | 选择文件、打开已有书或转换任务 | 导入后即返回书籍 ID，后台解析。列表显示书名、状态、上次操作时间。重复导入相同文件可打开已有书。 |
| 目录与正文 | 检查章名、顺序、章首章尾及全文，拆分、合并、改名、跳过或恢复章节，修正错行 | 保留原文件与来源位置。修改后保存新的编辑版本，汇总保留和跳过的章节数。空章、疑似扫描页和错序风险可定位。 |
| 音色试听 | 默认用当前章节的一段正文，也可选取含人名、数字、英文的片段。一次勾选多个音色，逐个点播，选择整书音色 | 建议至少提供 3 个可试听普通话音色及 1 个英文音色。比较时固定原文与语速。显示名称、语言、加载状态；若某音色不可用，保留其余样音。允许重复播放和重新选择。 |
| 任务与下载 | 开始生成、离开页面、回来查看、请求暂停、继续或重试、下载 | 显示当前章、完成片段数、总片段数、失败位置及各章下载入口。关闭标签页后后台继续。每章 MP3 校验通过即可下载。转换结果页将「下载有章节的 M4B」作为主操作，显示书名、音色、已生成章数 / 计划章数、总播放时长和整书文件名及大小。章节表按朗读顺序列出序号、章名、MP3 文件名、在 M4B 中的起止位置、本章时长、大小、状态和下载入口。重新选音色生成新的音频版本。 |

## 输入格式与目录判定

| 输入 | 实现 | 需要人工处理的情况 |
| --- | --- | --- |
| EPUB | 读 OPF spine 确定正文顺序，读 EPUB 3 nav 或 EPUB 2 NCX 的标题与片段锚点，以同一 XHTML 中的不同锚点切章。目录未覆盖的可读正文列入待核对段。 | 目录与正文顺序冲突、锚点失效、多个目录项指向同一位置时显示来源与预览，允许人工校正。 |
| MOBI、AZW3 | 使用 calibre 的 ebook-convert 生成工作副本 EPUB，再走同一解析器。保留原文件，记录转换工具版本。 | 无法打开、受保护或转换后目录为空时显示原因，允许改用可读取文件或手工分章。[calibre 输入格式](https://manual.calibre-ebook.com/faq.html#what-formats-does-calibre-support-conversion-to-from) |
| 文本 PDF | 逐页提取正文，优先按书签映射章节和页码，同页多个标题用正文定位。无书签时用标题模式提出候选，提供按页预览、手工设章和明确命名的页段。 | 标出低文本量页和疑似多栏页供核对。混合扫描文件列出受影响页，由用户确认跳过或替换源文件。整本无可读正文时停止并提示需要 OCR。 |

正文保留来源定位（EPUB 路径和锚点，或 PDF 页码）。页眉、页脚、连字符、断行与脚注的清理先生成可核对的朗读稿。修正与跳过只作用于编辑稿。固定版式、图表与公式按 Intent 提示用户核对。第一版不承诺扫描书 OCR 或复杂版面自动还原。

## 任务数据与恢复

| 数据 | 关键字段及约束 |
| --- | --- |
| source / book | source_id、原文件 SHA-256、格式、文件位置、书名、作者和封面。按内容摘要识别重复导入。 |
| revision / chapter | book_id、revision_id、chapter_id、排序、章名、来源位置、校正正文和是否朗读。开始生成后冻结该编辑版本。 |
| job / segment | job_id、revision_id、语音引擎及模型版本、音色、语速、分句规则版本、状态。每段含章 ID、顺序、实际朗读文本、缓存键、音频路径、样本数和错误。 |
| artifact | job_id、输出类型、文件路径、字节数、时长和校验结果。文件写在数据目录，数据库只记录元数据。 |

导入任务状态为“解析中 → 待核对”或“导入失败”。生成任务从“排队 → 合成 → 封装 → 完成”，可进入“已暂停”或“失败”。暂停在当前片段完成后生效。每台电脑默认一次运行一个整书任务；用户连续点击“生成”时，同一请求标识只创建一个任务。

后台按段落和中英文标点切分，超过所选引擎长度限制的句子再分片。缓存键包含实际朗读文本、语言、引擎与模型版本、音色、语速及影响发音的词典与参数。每段先写临时文件，解码检查采样率和非零时长后原子改名，再提交完成状态。重启时将遗留运行任务置为可继续，核对缓存后只生成缺失或损坏片段。封装失败可以直接重做封装。磁盘满时保留已完成段并显示所需操作。旧版已导出的书持续可下载。

## 网页与后台接口

以下是自有网页需要补齐功能时的接口契约。若现成网页通过验收，可直接使用其已验证操作。服务只监听本机回环地址，文件通过内部 ID 访问。

| 请求 | 作用与响应 |
| --- | --- |
| POST /api/books | multipart 上传单个电子书，返回 202 和 book_id；相同内容已存在时返回对应书籍。 |
| GET /api/books/{id} | 返回解析状态、元数据、当前 revision、章节摘要和带来源位置的警告。 |
| GET /api/books/{id}/chapters/{cid} | 按需载入正文和定位，避免首次打开就传输全书。 |
| PUT /api/books/{id}/revision | 提交基于指定版本的编辑，返回新 revision_id。版本过期返回 409 并提示刷新。 |
| GET /api/voices、POST /api/previews | 列出已安装音色，提交同段原文、音色和速度，返回可查询与播放的样音 ID。试听使用与整书相同的合成配置。 |
| GET /api/previews/{id} | 返回准备状态、失败原因或完成后的本地音频 URL。 |
| POST /api/jobs、GET /api/jobs/{id} | 按书籍版本、音色与格式建立任务，返回 202、job_id；查询返回状态、进度和可用操作。 |
| POST /api/jobs/{id}/pause、/resume、/retry | 请求暂停、继续或重试，对已满足的重复请求返回当前状态，无效状态转换返回 409。 |
| GET /api/artifacts/{id} | 下载已校验的 M4B、单章 MP3 或 ZIP。GET /api/jobs/{id} 返回计划与完成章数、总播放时长（毫秒）、M4B 文件名、大小与下载 ID，以及按顺序排列的章节列表（ID、标题、MP3 文件名、起止毫秒、播放时长、字节数、状态、下载 ID）。M4B 的章节位置与总时长取自成品探测，未就绪时为空。 |

## 音频封装与手机交付

片段统一采样格式，按已确认的顺序拼接，按实际 PCM 样本数累计章起点与终点，再编码为 AAC 并写入 M4B。保留书名、作者、可用封面和 UTF-8 章名。以 ffprobe 核对章数、标题、时间单调性和总时长，校验成功后发布成品。M4B 命名为「书名 - 音色 - 版本.m4b」，与各章 MP3 共用合成缓存。分别记录两种格式的导出状态，只有全部所需成品通过校验才显示整书转换完成。若某一格式失败，保留成功成品并允许单独重试。逐章编码和校验 MP3，只需该章的合成片段。每个版本使用独立目录，形如《示例书》/v01/001 - 序言.mp3。序号按确认后的朗读顺序从 1 开始，宽度取 3 与总章数位数中的较大值。保留中文，替换路径分隔符、控制字符和 Windows 非法字符，去除尾部空格与句点，限制标题长度，空标题回退为「未命名章节」。重名由章序区分，同一任务重试使用同一名称。写入书名、章名和轨道序号。逐章写临时文件，校验可解码、非零时长后原子发布，并记录大小和章节 ID。ZIP 仅在用户要求打包时生成。分章限制了单文件的范围，单个特长章的体积仍取决于时长与码率。[FFmpeg 容器与章节元数据](https://ffmpeg.org/ffmpeg-formats.html#Metadata-1)

用户将 M4B 复制到 Android 后用 Voice 导入，或在 iPhone 上从“文件”导入 BookPlayer，通过内嵌目录选章。需要分批传输时，可以只复制所需章节的 MP3，按编号组织为同一本书。章节随文件传递，书签和播放进度由各播放器维护。换音色或改正文导出新文件名，避免覆盖正在听的版本。

## 远程仓库与按机安装

仓库保存应用代码、网页模板、数据库迁移、锁定的依赖、第三方版本和模型校验清单、示例配置、启动脚本以及可再分发的小型测试书。远程仓库为 `git@git.ustc.edu.cn:luogd/relaxbook.git`。换电脑时，由接手者自行检查并配置该机的 SSH 连接，用 git ls-remote 验证仓库访问后检出代码。个人电子书、模型权重、音频和本机配置置于 Git 工作区之外的数据目录。

约定入口为 setup、doctor、start 三个命令，README 给出 Windows PowerShell 与 macOS/Linux 终端示例。setup 在隔离环境中安装固定版本，按配置获取模型。doctor 检查 Python、模型及音色、calibre、FFmpeg/ffprobe 版本、数据目录写权限和可用空间。start 启动后台、工作进程和本机网页；端口占用时提示可用地址。每台机器通过配置指定 data_dir、model_dir、模型、端口和并行度。模型和语言资源备齐后，断网验收应可通过。

第一台候选机器实际为 Windows、Intel i5-1240P、约 16 GB 内存、Iris Xe，已找到 calibre 8.0.1，当前 PATH 未找到 ffmpeg 和 ffprobe。先走 CPU 路径并记录真实速度。第二台电脑从干净检出起步验证同一个版本和样书；各操作系统的支持状态以实际安装和转换记录标注。未来迁移到服务器可沿用网页与任务接口，通过配置迁移数据目录与模型位置，届时再设计认证、HTTPS 和多用户隔离。

## 实施顺序与验收

| 阶段 | 交付物 | 通过条件 |
| --- | --- | --- |
| 1 选定复用方案 | 两个现成网页的试用记录，样音和样书、版本及缺口清单 | 同一中文书段试听至少 3 种普通话音色，英文段试听至少 1 种。用户对入围的 2 种中文音色各听 10 分钟并选定可长期听的一种。记录中英混排、多音字、数字、漏读和重复。 |
| 2 打通一本书 | Windows 本地网页、可修改的章节、完整中文书的 M4B 与分章 MP3、转换结果页 | 从浏览器导入至下载均可操作。逐章核对标题和首尾，抽听中段；在整书仍生成时单独下载并播放第 1 章；校验同名、空名、含斜杠的标题均得到稳定且唯一的合法文件名。按文件名排序与目录一致，连续播放和跳到第 2 章时均能听到对应正文。用含 3 章且两章同名的样书验收。结果页应为 3/3 章，3 个 MP3 文件名唯一，能分别下载。逐行比对 M4B 内嵌的章名、顺序与起止位置，总时长和各章时长按秒显示，与成品探测值的误差不超过 1 秒。在两种手机播放器分别导入同一 M4B 并跳转到三章开头。记录设备、输入字数、生成耗时、音频时长、大小及是否收费。 |
| 3 验证输入与恢复 | 另外一份中文 EPUB、英文 EPUB、MOBI、AZW3、文本 PDF、扫描 PDF 和故障记录 | 四种可读格式逐一转出并导入手机。扫描件有清楚提示。生成中关标签页后任务继续；强制结束工作进程后能复用已完成片段。模拟封装失败后可只重做封装。 |
| 4 验证日常使用与复装 | 两端真机记录，另一台电脑的全新安装记录 | Android 与 iOS 分别在电脑关闭、手机断网时听 30 分钟，验证章节跳转、倍速、耳机、来电恢复、锁屏、睡眠定时及书签，重新打开续播偏差不超过 5 秒。另一台电脑从同一 Git 版本完成配置、转换和下载。 |

验收按转换器、语音、手机系统及安装环境分别记录。阻塞条件是样书漏读或错序、用户找不到能长期听的音色、无法离线续播，或第二台机器无法按说明复装。等待时间以每小时成品音频所需的生成时间报告，结合用户是否接受再设性能上限。云端部署不参与本版验收。

执行时按[第一版验收清单](ACCEPTANCE.md)准备样书，核对下载成品，记录用户试听、双端真机和换机复装结果。
