# RelaxBook 第一版验收清单

[实现规格](SPEC.md)规定产品行为。本清单供开发者、测试者和使用者共同验收。先用三章小书发现可复现的问题，再用平时会读的完整书和手机确认日常体验。规格、清单和实际结果分别保存。

## 准备一份能对答案的样书

使用可再分发的自写中文 EPUB。三章标题依次为「序言」「出发」「出发」，首句分别以「清晨的列车」「午后的车站」「傍晚的灯光」开头，每章的末句也各不相同。事先从原稿抄录标题、首句、末句和一个中段句子，保存为预期清单。三段正文长度取不同值，方便发现时长或文件串章。预期目录与首尾句由原稿确定，成品时长在生成后测量。

另准备一本日常阅读的完整中文书（成品至少 30 分钟）、英文 EPUB、有书签的文本 PDF、无 DRM 的 MOBI 和 AZW3，以及仅含扫描图像的 PDF。空章名和含斜杠的章名可用小书的编辑副本验证。

## 第一轮：开发者从网页生成并核对成品

| 编号 | 怎样验 | 通过条件 |
| --- | --- | --- |
| A1 导入与编辑 | 在网页导入小书，核对目录、首尾句。在副本上进行改名、拆分、合并和跳过，刷新后重开。 | 顺序与原稿一致，同名两章保留各自正文；编辑稿可恢复，重新生成时使用确认后的目录。 |
| A2 两种格式 | 用原三章版本生成一次。第一章完成时单独下载 MP3，全书完成后下载 M4B 和其余 MP3。 | 同一次语音合成得到一本带内嵌目录的 M4B 和三个可独立播放的 MP3。文件名为「001 - 序言.mp3」「002 - 出发.mp3」「003 - 出发.mp3」。抽听各章首、中、末句，内容与原稿相符。空名和非法字符副本可得到有效、唯一、排序正确的文件名。 |
| A3 结果页 | 用下方命令读取下载文件，并逐行对照网页。刷新网页后再次下载。 | 页面为 3/3 章，整书文件名、大小、总播放时长及每章名称、顺序、MP3 文件名、大小、起止位置和时长均可核对。M4B 目录有 3 项，章起止依序衔接。网页秒值与成品对应边界或时长相差至多 1 秒；大小单位换算后按界面显示精度一致。各链接指向对应的可解码音频。 |
| A4 格式边界 | 依次导入 EPUB、MOBI、AZW3、文本 PDF，走到导出和手机导入；另导入扫描 PDF。 | 前四种可读样本保留完整正文与确认后的章序。PDF 抽查跨页顺序和页眉。扫描书明确提示需要 OCR，用户可定位原因。 |
| A5 中断与重试 | 生成多章时先关标签页再打开；取得第一章后强制结束工作进程并重启；在测试目录人为制造一次封装写入失败，恢复可写后重试。 | 浏览器重开能找回任务。比较恢复前后片段摘要和合成调用日志，已成功的片段未重新合成。封装失败可定位、可单独重试，成功成品仍能下载。任务只在两种成品都通过校验时报告完成。 |

在成品所在目录运行，文件名换成本次实际下载值。M4B 的章节表用来核对起止位置，MP3 单独探测可发现链接错指另一章。

```sh
ffprobe -v error -show_format -show_chapters -of json "示例书.m4b"
ffprobe -v error -show_format -of json "002 - 出发.mp3"
ffmpeg -v error -xerror -i "示例书.m4b" -map 0:a:0 -f null -
```

## 第二轮：听感、手机与换机

| 编号 | 执行人及操作 | 通过条件 |
| --- | --- | --- |
| B1 音色 | 开发者提供同文同速的至少 3 个普通话音色和 1 个英文音色。使用者用含多音字、人名、数字和英文的真实书段试听，对入围的 2 个普通话音色各听 10 分钟。 | 使用者选出至少一个愿意长期听的音色，并记录选用音色和影响理解的具体读音或停顿。抽听完整中文书时核对有无整段漏读、重复或截断。 |
| B2 真机 | 同一份小书 M4B 分别导入 Android 的 Voice 与 iOS 的 BookPlayer。逐章跳转并听首句，再试按序导入三个 MP3。换用长书，关闭电脑，手机开飞行模式、锁屏播放 30 分钟，记录暂停位置，重启播放器后续播。 | 两端均能从目录跳到预期首句，MP3 可按序连播。断网锁屏期间可播放，续播偏差不超过 5 秒。分别验证倍速、耳机控制、睡眠定时和书签。退出飞行模式后另测来电中断与恢复。 |
| B3 全新安装 | 在第二台电脑上，自行配置 SSH，检出同一提交，按 README 安装、检查、启动，备齐模型后断网，用浏览器转换小书。 | 无需第一台电脑的本机路径或缓存，即可试听、导出两种音频并查看正确结果。记录操作系统、运行时、模型与工具版本。 |

## 如何给出结论

A1–A5 通过可交付**电脑端转换样版**。第一版整体通过还需 B1–B3 的实测结果。缺少某个平台时标为「待验证」，例如「电脑端和 Android 已通过，iOS 待验证」。音频与原文错位、静默漏章、成品无法导入、结果页报错时长、离线续播丢失或换机无法复装，均需修复并复测受影响的场景。每小时成品所需生成时间记录实测值，由使用者决定是否可接受。

每轮在测试记录中填入 Git 提交、样书版本、电脑与手机系统、播放器版本、模型及音色。每项填写「通过 / 失败 / 待验证」及证据位置。A3 保存结果页截图与探测 JSON，A5 保存恢复日志，B1 保存试听意见，B2 保存实测跳章首句和续播偏差。私人书籍和音频保存在测试机器上。
